Lecture 03

Advanced Encryption Standard

DES replaced its ad-hoc S-boxes with one algebraic idea — the inverse in GF(2⁸) — and built every other stage to be fast, invertible, and provably linear.

AES at a glance

Also known as Rijndael, developed by Vincent Rijmen and Joan Daemen, selected by the five-year NIST standardization process in 2001.

AES specification
Block size128 bits, fixed
Key size128 / 192 / 256 bits
Rounds10 / 12 / 14, matching the key size
Underlying structureSubstitution-Permutation Network (SPN) — not Feistel
The structural difference from DES worth stating

DES is Feistel: half the block passes through unchanged each round, which is why decryption reuses the same F. AES is an SPN: every byte of the whole block is transformed every round, so encryption and decryption use genuinely different, mutually inverse operations (InvSubBytes, InvShiftRows, InvMixColumns) rather than the same circuit run backwards.

Mathematical background: fields

Definition — Field

A set 𝔽 with two operations, addition and multiplication, supporting +, −, ×, ÷ — division by every nonzero element. For a, b, c ∈ 𝔽:

Associativity: (a + b) + c = a + (b + c), (ab)c = a(bc) Commutativity: a + b = b + a, ab = ba Distributivity: a(b + c) = ab + ac Identities 0 and 1 exist. Every a has an additive inverse −a. Every a ≠ 0 has a multiplicative inverse a⁻¹, with aa⁻¹ = 1.
  • ℚ, ℝ, ℂ are fields.
  • ℤ is not a field — 3 ≠ 0 but 3⁻¹ = 1/3 ∉ ℤ.
  • ℤm = {0, 1, …, m−1} under addition and multiplication mod m: a field iff m is prime. If m is composite, ℤm is not a field.
Definition — Finite field

A field with finitely many elements. The simplest examples are ℤp for p prime.

Worked example — ℤ₅ = {0,1,2,3,4}
2 + 4 = 1 (mod 5) 2 · 3 = 1 (mod 5) ⟹ 3 is the multiplicative inverse of 2

Representing bytes in GF(2⁸)

An AES byte is 8 bits: b₇b₆b₅b₄b₃b₂b₁b₀. Represent it as a polynomial over 𝔽₂:

b₇X⁷ + b₆X⁶ + ⋯ + b₁X + b₀, each bᵢ ∈ {0, 1}
Worked example
11001011 ⟷ X⁷ + X⁶ + X³ + X + 1

There are exactly 2⁸ = 256 such polynomials of degree less than 8 — one per byte value. AES fixes the irreducible polynomial

P(X) = X⁸ + X⁴ + X³ + X + 1 (irreducible in ℤ₂[X])

and identifies the 256 byte values with the elements of

GF(2⁸) = 𝔽₂[X] / ⟨X⁸ + X⁴ + X³ + X + 1⟩

All arithmetic — AES's confusion, diffusion and key schedule alike — happens inside this one field.

Why GF(2⁸) and not something bigger

GF(2⁸) matches the natural 8-bit byte of a computer and gives strong nonlinearity cheaply. A larger field such as GF(2¹⁶) would make the S-box far more expensive without a comparable security gain — this is exactly the "practical security" trade-off from Lecture 2.

GF(2⁸) addition and multiplication

The two operations
  • Addition ↔ bitwise XOR (no carrying — coefficients are mod 2).
  • Multiplication ↔ polynomial multiplication, reduced modulo P(X).
  • Every nonzero byte has a multiplicative inverse, because P(X) is irreducible.
Worked example — addition
A(X) = X⁷ + X⁶ + X³ + X + 1 (= 11001011) B(X) = X⁴ + X³ + 1 (= 00011001) A(X) + B(X) = X⁷ + X⁶ + X⁴ + X as bytes: 11001011 ⊕ 00011001 = 11010010

Addition in GF(2⁸) is literally bitwise XOR — no modular reduction is ever needed, because a degree-≤7 polynomial plus another degree-≤7 polynomial is still degree ≤7.

Worked example — multiplication
A(X)·B(X) mod P(X) = (X⁷+X⁶+X³+X+1)(X⁴+X³+1) = (X¹¹+X¹⁰+X⁷+X⁵+X⁴) + (X¹⁰+X⁹+X⁶+X⁴+X³) + (X⁷+X⁶+X³+X+1) = X¹¹ + X⁹ + X⁵ + X + 1 (mod X⁸+X⁴+X³+X+1) = X⁷ + X⁶ + X³ + X² + 1

Multiplication, unlike addition, can push the degree above 7, which is exactly when the reduction mod P(X) bites.

Inverses: the extended Euclidean algorithm

Theorem — Bézout for polynomials

Let 𝔽 be a field and A(X), P(X) ∈ 𝔽[X]. There exist S(X), T(X) ∈ 𝔽[X] with

P(X)S(X) + A(X)T(X) = gcd(P(X), A(X))

Since P(X) is irreducible and A(X) is not a multiple of it, gcd(P, A) = 1, so A(X)T(X) ≡ 1 (mod P(X)) — meaning T(X) is exactly A(X)⁻¹ mod P(X).

The Euclidean algorithm (finds the gcd)
R₀ := P, R₁ := A Rᵢ = Qᵢ·Rᵢ₊₁ + Rᵢ₊₂ (repeated division with remainder) …until the remainder is 0; the last nonzero remainder is the gcd.
Extended algorithm (also finds S, T)
S₀ = 1, S₁ = 0, T₀ = 0, T₁ = 1 Sᵢ₊₁ = Sᵢ₋₁ − SᵢQᵢ, Tᵢ₊₁ = Tᵢ₋₁ − TᵢQᵢ Invariant: P(X)Sᵢ(X) + A(X)Tᵢ(X) = Rᵢ(X) for every i

Proof by induction: the base cases i = 0, 1 are immediate from the definitions of S, T. For the step,

PSᵢ + ATᵢ = P(Sᵢ₋₂ − Sᵢ₋₁Qᵢ₋₁) + A(Tᵢ₋₂ − Tᵢ₋₁Qᵢ₋₁) = (PSᵢ₋₂ + ATᵢ₋₂) − (PSᵢ₋₁ + ATᵢ₋₁)Qᵢ₋₁ = Rᵢ₋₂ − Rᵢ₋₁Qᵢ₋₁ = Rᵢ
Worked example — inverse of A(X) = X⁷+X⁶+X³+X+1 mod P(X)

Step 1 — Euclidean algorithm:

R₀ = P = X⁸+X⁴+X³+X+1 R₁ = A = X⁷+X⁶+X³+X+1 X⁸+X⁴+X³+X+1 = (X+1)(X⁷+X⁶+X³+X+1) + (X⁶+X²+X) Q₀ = X+1, R₂ = X⁶+X²+X X⁷+X⁶+X³+X+1 = (X+1)(X⁶+X²+X) + 1 Q₁ = X+1, R₃ = 1 ← gcd X⁶+X²+X = (X⁶+X²+X)·1 + 0 Q₂ = X⁶+X²+X

Step 2 — back-substitute (or run the S, T recurrence):

S₂ = S₀ − S₁Q₁ = 1, T₂ = T₀ − T₁Q₁ = −(X+1) S₃ = S₁ − S₂Q₂ = −(X+1), T₃ = T₁ − T₂Q₂ = 1 + (X+1)² = X² ⟹ P(X)(X+1) + A(X)·X² = 1

Result:

(X⁷+X⁶+X³+X+1)⁻¹ = X² (mod X⁸+X⁴+X³+X+1)
What to practice

Every exam-style inverse computation is this same three-line shape: divide twice (three lines if the gcd isn't reached after one step), then substitute back once. Over GF(2⁸), subtraction and addition are the same XOR, so "−" and "+" in the S, T recurrence can be read as "⊕" throughout.

Round structure

Encryption: AddRoundKey once, then N−1 full rounds (SubBytes → ShiftRows → MixColumns → AddRoundKey), then a final round that omits MixColumns. Decryption runs the inverse operations in reverse order, with the round keys applied in reverse.

The four transformations, and which rounds use them
TransformationWhat it doesRounds
SubBytesByte-by-byte substitution using the S-boxAll rounds
ShiftRowsA simple row-by-row permutationAll rounds
MixColumnsSubstitutes each byte of a column as a function of the whole columnRounds 1–9 (omitted in the final round)
AddRoundKeyBitwise XOR of the state with a slice of the expanded keyAll rounds, plus once before round 1
Which stage does what

SubBytes is the only nonlinear step and supplies confusion. ShiftRows and MixColumns are both linear and supply diffusion — ShiftRows across rows, MixColumns down columns, so together every output byte depends on every input byte within two rounds. AddRoundKey is the only place the key enters.

Why the S-box is built this way

The nonzero elements of GF(2⁸) satisfy a²⁵⁵ = 1 (Lagrange's theorem on the multiplicative group), so for every a ≠ 0:

a⁻¹ = a²⁵⁴
Why the inverse gives confusion

The inverse is the power map a ↦ a²⁵⁴ — a very high-degree, highly nonlinear function of the input bits. That nonlinearity is exactly what confusion means: a simple algebraic description of the key–ciphertext relationship should not exist. It is the field-theoretic analogue of DES's ad-hoc S-boxes, except here it is derived from one clean algebraic fact rather than hand-tuned.

The S-box itself is not the raw inverse map — a pure inverse has an undesirable fixed point structure, so an invertible affine transformation is layered on top to remove it.

Definition — S-box construction

Given byte x = x₇x₆x₅x₄x₃x₂x₁x₀:

  1. Compute y = x⁻¹ in GF(2⁸) (by convention 0⁻¹ := 0).
  2. Apply the fixed affine map z = M·y + c over 𝔽₂:
    ⎛1 0 0 0 1 1 1 1⎞ ⎛y₀⎞ ⎛1⎞ ⎛z₀⎞ ⎜1 1 0 0 0 1 1 1⎟ ⎜y₁⎟ ⎜1⎟ ⎜z₁⎟ ⎜1 1 1 0 0 0 1 1⎟ ⎜y₂⎟ ⎜0⎟ ⎜z₂⎟ ⎜1 1 1 1 0 0 0 1⎟ ⎜y₃⎟ + ⎜0⎟ = ⎜z₃⎟ ⎜1 1 1 1 1 0 0 0⎟ ⎜y₄⎟ ⎜0⎟ ⎜z₄⎟ ⎜0 1 1 1 1 1 0 0⎟ ⎜y₅⎟ ⎜1⎟ ⎜z₅⎟ ⎜0 0 1 1 1 1 1 0⎟ ⎜y₆⎟ ⎜1⎟ ⎜z₆⎟ ⎝0 0 0 1 1 1 1 1⎠ ⎝y₇⎠ ⎝0⎠ ⎝z₇⎠
  3. Output z = z₇z₆z₅z₄z₃z₂z₁z₀.
Worked examples
00 → x=00000000 →ˣ⁻¹ y=00000000 → z=01100011 → 63 01 → x=00000001 →ˣ⁻¹ y=00000001 → z=01111100 → 7C CB → x=11001011 →ˣ⁻¹ y=00000100 → z=00011111 → 1F

These are exactly the 00, 01 and CB entries of the S-box table above — the table is precomputed once from this construction and then just looked up.

ShiftRows

Definition — ShiftRows
  • Row 1: no change
  • Row 2: 1-byte circular left shift
  • Row 3: 2-byte circular left shift
  • Row 4: 3-byte circular left shift

InvShiftRows shifts right by the same amounts.

Worked example
87 F2 4D 97 87 F2 4D 97 EC 6E 4C 90 → 6E 4C 90 EC 4A C3 46 E7 46 E7 4A C3 8C D8 95 A6 A6 8C D8 95

ShiftRows spreads bytes across columns: after this step, each of the four columns contains one byte originally from every column, which is what lets MixColumns finish the job of mixing the whole state.

MixColumns

Each column of the state is left-multiplied by a fixed 4×4 matrix over GF(2⁸):

⎛02 03 01 01⎞ ⎛c₀,₀ c₀,₁ c₀,₂ c₀,₃⎞ ⎛d₀,₀ d₀,₁ d₀,₂ d₀,₃⎞ ⎜01 02 03 01⎟ ⎜c₁,₀ c₁,₁ c₁,₂ c₁,₃⎟ ⎜d₁,₀ d₁,₁ d₁,₂ d₁,₃⎟ ⎜01 01 02 03⎟ ⎜c₂,₀ c₂,₁ c₂,₂ c₂,₃⎟ = ⎜d₂,₀ d₂,₁ d₂,₂ d₂,₃⎟ ⎝03 01 01 02⎠ ⎝c₃,₀ c₃,₁ c₃,₂ c₃,₃⎠ ⎝d₃,₀ d₃,₁ d₃,₂ d₃,₃⎠ =: M

M is invertible over GF(2⁸); InvMixColumns multiplies by M⁻¹.

Worked example — one column
⎛X X+1 1 1 ⎞ ⎛87 (=X⁷+X²+X+1) ⎞ ⎜1 X X+1 1 ⎟ ⎜6E (=X⁶+X⁵+X³+X²+X) ⎟ ⎜1 1 X X+1⎟ ⎜46 (=X⁶+X²+X) ⎟ ⎝X+1 1 1 X ⎠ ⎝A6 (=X⁷+X⁵+X²+X) ⎠ first entry = X(X⁷+X²+X+1) + (X+1)(X⁶+X⁵+X³+X²+X) + 1(X⁶+X²+X) + 1(X⁷+X⁵+X²+X) = X⁸+X⁶+X⁴+X³+X² = X⁶+X²+X+1 (mod X⁸+X⁴+X³+X+1) = 0100 0111 = 47

Repeating for all four columns of the ShiftRows output:

87 F2 4D 97 47 40 A3 4C 6E 4C 90 EC → 37 D4 70 9F 46 E7 4A C3 94 E4 3A 42 A6 8C D8 95 ED A5 A6 BC
Why the matrix entries are 01, 02, 03

Multiplying by 01 is the identity; multiplying by 02 is X (a left shift, reduced mod P(X) if it overflows); multiplying by 03 is X+1, i.e. "double, then XOR the original in". These are the cheapest nontrivial GF(2⁸) multiplications, which is why MixColumns is fast in both hardware and software despite mixing every byte in a column.

AddRoundKey

Definition — AddRoundKey

Bitwise XOR of the 128-bit state with 128 bits of the expanded key. Its own inverse: XOR the same round key again.

Worked example
47 40 A3 4C AC 19 28 57 EB 59 8B 1B 37 D4 70 9F 77 FA D1 5C 40 2E A1 C3 94 E4 3A 42 ⊕ 66 DC 29 00 = F2 38 13 42 ED A5 A6 BC F3 21 41 6E 1E 84 E7 D2 current state round key output one byte: 47 = 01000111 AC = 10101100 ⊕ ---------------- EB = 11101011

Key expansion

The cipher key K, as four 32-bit words, is expanded into 4(Nr+1) words W(0), W(1), … — one 128-bit round key per round plus the initial whitening key.

Definition — key expansion recurrence
W(i) = { W(i−4) ⊕ W(i−1) if i is not a multiple of 4 { W(i−4) ⊕ T(W(i−1)) if i is a multiple of 4

where, writing W(i−1) = (w₀,ᵢ₋₁, w₁,ᵢ₋₁, w₂,ᵢ₋₁, w₃,ᵢ₋₁), the transformation T does:

  1. RotWord — circular left shift by one byte: (w₁,ᵢ₋₁, w₂,ᵢ₋₁, w₃,ᵢ₋₁, w₀,ᵢ₋₁)
  2. SubWord — apply the S-box to each byte: (S(w₁,ᵢ₋₁), S(w₂,ᵢ₋₁), S(w₃,ᵢ₋₁), S(w₀,ᵢ₋₁))
  3. Compute the round constant r(i) = X(i−4)/4 in GF(2⁸)
  4. T(W(i−1)) = (S(w₁,ᵢ₋₁) ⊕ r(i), S(w₂,ᵢ₋₁), S(w₃,ᵢ₋₁), S(w₀,ᵢ₋₁))
Reading this recurrence for an exam
  • Every fourth word is "refreshed" through the S-box and a round-dependent constant; the three words in between are plain XOR chains. This is what breaks the linearity that made the LFSR cipher's known-plaintext attack (Lecture 1) work.
  • The S-box appears twice in AES: once in SubBytes on the data, once in SubWord in the key schedule. It is the single nonlinear primitive the whole cipher is built from.
  • The round constant r(i) makes each group of four expanded words distinct even if RotWord+SubWord alone would repeat a pattern.

AES: security

Only AddRoundKey uses the key directly — but because SubWord folds the key through the S-box every four words, every round key still depends nonlinearly on the original key.

Brute force

2128 candidate keys for AES-128 — utterly infeasible, unlike DES's 256.

Best known attack — biclique cryptanalysis

Bogdanov, Khovratovich and Rechberger, ASIACRYPT 2011. A small, structured improvement over brute force:

AES-128: 2^126.1 AES-192: 2^189.7 AES-256: 2^254.4

Each is only a few bits better than exhaustive search — nowhere near a practical break. AES-128 remains unbroken in any practical sense.
