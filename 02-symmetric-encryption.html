Lecture 02

Symmetric Encryption

How a real block cipher is built, why Feistel makes decryption free, and why doubling a key length does not double security.

Symmetric encryption

Sender and receiver hold the same key — hence symmetric / private / secret key encryption. The transmitted ciphertext is Y = E(K, X) and the receiver computes X = D(K, Y).

  • Covers: classical encryption, block ciphers (DES, AES, ARIA, SEED), stream ciphers (RC4, ChaCha).
  • Pro: faster than asymmetric (public key) encryption.
  • Con: the key-sharing problem, and a large number of keys — n parties who all want to talk pairwise need n(n−1)/2 keys.

Why a stream key is single-use

The keystream is XORed in, so a known plaintext hands over the key directly:

M ⊕ C = M ⊕ (M ⊕ k) = k

And two messages under the same keystream give C₁ ⊕ C₂ = M₁ ⊕ M₂.

Designing a block cipher

A symmetric block cipher is a sequence of rounds built from substitutions and permutations, controlled by a key. The design parameters — a likely short-answer question:

  • Block size
  • Key size
  • Number of rounds
  • Subkey generation algorithm
  • Round function
  • Fast software / hardware encryption and decryption
  • Ease of security analysis

The first three trade security against speed; the last two are why an elegant cipher beats a complicated one.

Confusion and diffusion

The two fundamental design principles
  • Confusion — make the relationship between the key and the ciphertext as complex as possible.
  • Diffusion — spread the influence of each plaintext bit over many ciphertext bits.

Which building block delivers which:

  • Nonlinear substitution (S-box) ⇒ confusion
  • Permutation / linear mixing over several rounds ⇒ diffusion

DES and AES both repeat these two operations over many rounds. Neither alone is enough: substitution without permutation never spreads a change; permutation without substitution stays linear, and linear ciphers fall to the linear algebra seen in Lecture 1.

Design principle

A small change in the plaintext or the key should result in a large, seemingly unpredictable change in the ciphertext.

Avalanche effect

Changing one input bit should change many output bits. For an n-bit block cipher, the ideal is that a one-bit input change flips roughly half the output bits on average.

Repeated rounds amplify small differences:

small input difference → S-box → permutation/mixing → many changed bits
The caveat that gets examined

The avalanche effect is a useful design criterion, not a proof of security. A cipher can avalanche beautifully and still be broken — see linear cryptanalysis of DES.

Practical security and security strength

In practice the security of a system is estimated by the computational resources the best known attack requires. A cryptosystem counts as practically secure if either:

  • the cost of breaking the cipher exceeds the value of the encrypted information, or
  • the time to break it exceeds the useful lifetime of the information.

Both are economic statements, not mathematical ones — which is the contrast with the one-time pad's perfect secrecy.

Feistel cipher structure

First designed by Horst Feistel in 1973. Input: a plaintext block of 2w bits and a key K. The block is split into halves L₀ and R₀, which pass through n identically-structured rounds and are recombined into the ciphertext.

One Feistel round
Lᵢ = Rᵢ₋₁ Rᵢ = Lᵢ₋₁ ⊕ F(Rᵢ₋₁, Kᵢ)

Inverting a round, given (Lᵢ, Rᵢ):

Rᵢ₋₁ = Lᵢ Lᵢ₋₁ = Rᵢ ⊕ F(Lᵢ, Kᵢ)
The two consequences to state in an exam
  1. The round function F need not be invertible — it is only ever evaluated forwards, in both encryption and decryption. That frees the designer to make F as nonlinear and messy as they like.
  2. Decryption is the same circuit with the round keys reversed: Kn, Kn−1, …, K₁. One piece of hardware does both jobs.

DES: parameters

Adopted in 1977 by the National Bureau of Standards (now NIST) as FIPS PUB 46.

DES at a glance
Plaintext / ciphertext block64 bits
Key64 bits, including 8 parity bits — effective key length 56 bits
Rounds16, on a variant of the Feistel structure
Subkeys16 generated from the key, one per round, 48 bits each
Key scheduleEncryption K₁ → K₂ → … → K₁₆; decryption K₁₆ → K₁₅ → … → K₁

Overall flow: plaintext → initial permutation IP → 16 Feistel rounds → 32-bit halves swapped → IP⁻¹ → ciphertext.

DES: the round function

Each round takes the 32-bit half Ri−1 and the 48-bit subkey Ki, and runs four stages:

R (32 bits) → E: expansion/permutation → 48 bits → XOR with Kᵢ (48 bits) → 48 bits → S: eight S-boxes, 6 bits → 4 bits → 32 bits → P: permutation → 32 bits then Lᵢ = Rᵢ₋₁, Rᵢ = Lᵢ₋₁ ⊕ F(Rᵢ₋₁, Kᵢ)

The expansion exists so the 32-bit half can be XORed with a 48-bit subkey and so that each input bit feeds two S-boxes; the P permutation carries each S-box's output into different S-boxes next round, which is where the diffusion comes from.

DES: S-boxes

Eight S-boxes, Si : {0,1}6 → {0,1}4 for 1 ≤ i ≤ 8. They are the only nonlinear part of DES.

How to evaluate an S-box

For input b₀b₁b₂b₃b₄b₅:

  • Row = the outer two bits (b₀b₅), a number 0–3.
  • Column = the inner four bits (b₁b₂b₃b₄), a number 0–15.

Worked example — S₁(011011)
b₀b₅ = 0,1 → row 1 b₁b₂b₃b₄ = 1101 → column 13 S₁ row 1, column 13 = 5 = 0101

Six bits in, four bits out — which is also why the S-box is not invertible, and why Feistel's "F need not be invertible" matters.

A detail worth noticing

The shifts sum to 28 — a full rotation — so after round 16 the registers are back where they started. That is what lets decryption regenerate the subkeys in reverse order by rotating right instead of left.

DES: security analysis

All parts of DES are linear except the S-boxes.

Brute force — 256 candidate keys
  • CRYPTO '93 rump session: Michael Wiener presented a detailed key-search machine design — expected 1.5 days with 1993 technology for $100,000.
  • 1998: the Electronic Frontier Foundation built a key-search machine costing $250,000; record 56 hours, July 1998.
  • 1999: RSA Laboratory found a DES key in 22 hours 15 minutes.
Linear cryptanalysis (Mitsuru Matsui)
  • Generate 243 plaintext–ciphertext pairs: 40 days.
  • Find the key: 10 days.

It approximates the S-boxes by linear expressions that hold slightly more often than half the time, then accumulates the bias over huge numbers of pairs. The cost is in the data, not the computation.

Double DES and meet-in-the-middle

Double DES
For two independent 56-bit keys K₁, K₂: C = E(K₂, E(K₁, P)) P = D(K₁, D(K₂, C))

Total key length 56 + 56 = 112 bits, so exhaustive search naively looks like 2112.

But rearranging the encryption equation gives the meeting point:

E(K₁, P) = D(K₂, C)

Both sides can be computed from one key each, so the attacker never has to guess both at once.

Meet-in-the-middle attack

Assume a known plaintext–ciphertext pair (P, C).

  1. For every K₁ ∈ {0,1}56, compute XK₁ = E(K₁, P) and store the pair (XK₁, K₁) in a table.
  2. For every K₂ ∈ {0,1}56, compute YK₂ = D(K₂, C) and look YK₂ up in the table.
  3. If XK₁ = YK₂, then (K₁, K₂) is a candidate key. Verify it on a second plaintext–ciphertext pair — the 64-bit block is smaller than the 112-bit key space, so false matches are expected.
Time ≈ 2⁵⁷ Memory ≈ 2⁵⁶

Double DES therefore does not provide 112-bit security. It buys one bit of time over single DES, at the price of an enormous table.

The general lesson

Composing a cipher with itself trades memory for time; it does not add key strength. Any time an exam shows you a two-stage encryption with independent keys, reach for meet-in-the-middle and the 2n+1 / 2n cost pair.

Triple DES

Triple DES (EDE)
Enc(K = (K₁, K₂, K₃), P) = E(K₃, D(K₂, E(K₁, P))) Dec(K = (K₁, K₂, K₃), C) = D(K₁, E(K₂, D(K₃, C)))

Encrypt–decrypt–encrypt, not encrypt three times. Setting K₁ = K₂ = K₃ makes 3DES compute plain DES, which is how it stays backwards compatible with legacy equipment.

  • Standardised for financial applications in ANSI X9.17, 1985.
  • Plaintext size = ciphertext size = 64 bits.
  • Nominal key length: three-key 3DES 168 bits; two-key 3DES (K₁ = K₃) 112 bits.
  • Security strength: three-key 3DES gives only about 112-bit security, because of meet-in-the-middle attacks.
Triple DES weighed up
AttractionsSecure against the brute-force attacks that killed DES; compatible with legacy DES implementations
Weak points64-bit block size (small, relative to a 168-bit key); slow in software

The small block is a real problem, not a cosmetic one: with a 64-bit block, repeated ciphertext blocks start appearing after roughly 232 blocks by the birthday bound, which leaks plaintext structure regardless of key length. That, plus the software speed, is why AES replaced it.
